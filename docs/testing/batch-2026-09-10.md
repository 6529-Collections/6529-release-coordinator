## Scope and local proof

The unscoped sandbox `inbox:run` performs cheap intake, database/scope and Git
filtering first, then normal PR CI on owned temporary combined branches and the
existing service runtime for the exact combined sources. Supported requests are
self-contained staging tickets with verified `database_change: no`.

The full local check passed 347 tests on Node 24.19.0, lint, formatting,
workflow policy, package smoke and source preservation. New offline coverage:

- BA-01/02: one full combined run after cheap filtering; held tickets start none.
- BA-03/04: attributable singleton failure, useful survivors, and A/B individually
  passing but incompatible together; a union needs its own passing result.
- BA-06/07 boundary: whole cross-repository scope is preserved; missing scope,
  cross-profile or unsupported database/target inputs cannot become a candidate.
  Cross-ticket dependency declarations are not implemented.
- BA-08/09: changed inputs cannot reuse evidence; saved budgets and deterministic
  priority bound work and keep untested tickets visible.
- BA-10/11: baseline/runner uncertainty does not trigger code blame; repeat/resume,
  uncertain creation, journal compatibility and the same managed comments.
- BA-12/13: real Git conflicts, exact published trees/check identity, skipped and
  wrong-run rejection, actual checkout tree/parent verification, owned temporary
  cleanup, saved remote evidence revalidation, and sandbox-only writes.

These are local adapter/fixture tests, not real GitHub workflow proof. The full
matrix remains in [the testing guide](../merge-rehearsal-testing.md#planned-batch-acceptance).
