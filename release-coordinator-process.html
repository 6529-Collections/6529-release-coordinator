Release steps

    Current first version: The local CLI package is implemented and published. The frontend release skill uses it as a local preflight. Backend integration is next. The CLI saves every run locally and adds only a valid request to the local outbox. It does not send anything to a Coordinator yet. After a successful frontend preflight, the existing Release Bus process continues without reading this JSON. The trusted GitHub submission workflow, inbox, and remaining Coordinator steps are still the target process.

    Make sure every pull request is open, approved, has passed the checks required by its GitHub repository, and has no merge conflicts. Do not include pull requests that are not ready.

    How progress is saved: The Coordinator saves each step and its result. If something fails, the saved progress shows where the release stopped and what happened.
